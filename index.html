What is the 8-Puzzle Problem?

The 8-Puzzle is a sliding-tile puzzle played on a 3×3 grid holding eight numbered tiles and one blank space. Any tile adjacent to the blank can slide into it, which is equivalent to saying the blank itself moves up, down, left, or right. Starting from some scrambled arrangement, the goal is to reach a specified target arrangement using the fewest possible moves.

Framed as a search problem: each arrangement of tiles is a state, each legal slide is an action connecting two states, and solving the puzzle means finding a path through this state-space graph from the initial state to the goal state. Because the graph is far too large to draw by hand (181,440 reachable states for any given goal), it has to be explored algorithmically — which is exactly what BFS, DFS, DLS, IDDFS, Uniform Cost Search, Greedy Best-First Search, and A* are each designed to do differently. This build implements the search assigned for this submission: Depth-First Search.

Algorithm Info — Depth-First Search

Description

Depth-First Search (DFS) is an uninformed state-space search strategy that always expands the deepest unexpanded node in the current frontier first. It explores one branch of the search tree as far as it will go before backtracking to try alternatives, using a Last-In-First-Out (LIFO) stack to decide what to expand next.

Working Principle

Push the initial state onto a stack. Repeatedly pop the top state: if it is the goal, stop and reconstruct the path via parent pointers; otherwise, if it has not already been expanded, mark it explored and push each of its unvisited successors onto the stack. Because the stack is LIFO, the most recently generated state is always tried next, which is what drives the search deep into one branch before it ever backtracks to a sibling.

Advantages

  • Very low memory use relative to breadth-first strategies — the frontier only ever needs to hold one path's worth of siblings, not an entire level of the tree.
  • Simple to implement iteratively with an explicit stack (no priority queue or distance bookkeeping required).
  • Can find a solution quickly if a short path happens to lie along an early-explored branch.

Limitations

  • Not optimal — the first solution DFS finds is rarely the shortest one, since expansion order is driven purely by recency, not by cost.
  • Without a visited-set and a depth bound, DFS can wander down a very long, unproductive branch, or loop forever in a graph with cycles.
  • Solution quality is highly sensitive to the order successors are generated in (here: Up, Down, Left, Right).

Time Complexity

O(b^m), where b is the branching factor (2–4 for the 8-Puzzle, depending on the blank's position) and m is the maximum depth the search reaches — bounded in this implementation by the Max Depth Limit setting.

Space Complexity

O(b·m) — DFS only needs to remember the current path and the unexplored siblings hanging off it, which is why its memory footprint is so much lower than BFS's O(b^d).

Completeness

The 8-Puzzle's reachable state space is finite (181,440 states for a given parity class), so DFS with an explored-set is completein principle on this graph — it will not loop forever. In practice, an unbounded search can still take a very long time before it happens across the goal, which is why this build applies a depth cutoff and a node-generation cap for a bounded, responsive demo. With those bounds in place, DFS is not guaranteed complete: a solution can exist beyond the depth limit and be missed.

Optimality

Not optimal. DFS returns the first goal it reaches on the stack, not the cheapest one — unlike BFS or Uniform Cost Search on unit-cost graphs, it gives no guarantee that the reported path is the shortest possible solution.
